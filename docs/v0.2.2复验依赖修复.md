# v0.2.2 候选：已交付成果可以送审

独立验证应发生在作者交稿后、成果批准前。旧门禁把所有任务依赖都要求为 `approved`，使正确处于 `in_review` 的作者无法交给验证角色。本次增加显式复验依赖，不把未审成果改成已批准。

旧的 `depends_on: ["AUTHOR"]` 和 `{ "task_id": "AUTHOR" }` 保持执行依赖语义，仍要求该任务已批准。只有新对象明确填写 `relation: "review"`，才能向 `mcm-verifier` 或 `mcm-reviewer` 交付作者处于 `in_review`／`approved` 的固定成果。

复验依赖须提供 `handoff_ref` 的项目相对路径和 SHA，以及非空 `output_refs`。每份输出包含 `artifact_id/path/version/sha256`，同时属于作者声明的输出、作者实际读回、制品登记和复验任务输入。交接文件与真实字节均重新核对；过期、撤回、失效或上游变化继续拒绝。不能把 `pending:*` 作者身份当作实际作者，孩子的实际非作者身份还须在创建后读回、验收时确认。

审阅者的写范围不能覆盖候选、上游证据或交接文件。检查规范化路径及符号链接／junction；这是工具工作流约束，不是 OS 文件系统隔离，不检测硬链接的物理别名。完全访问下仍须遵守单写入者与只读原稿约定，不能声称“系统不可写”。

来源、任务和参数指纹在预检、执行前和原生工具体中重新核对。Python `context-pack` 同时检查依赖就绪，但它不发放 Host 名额或人工批准。未知、过期、未验证或已满的容量、暂停、深度、角色和一次许可仍会阻断派发。容量来源缺失时，本修复不会使真实会话可以派发。

兼容性修复还包括将任务卡的相对 `project_root` 按已知项目根解析，保持原生 `cwd` 必须是同一绝对根；以及拒绝把 JSON `true` 当作版本 `1` 的 Python 诊断错误。

实际执行的最新软件检查为 **44 项根目录测试、115 项项目测试、48 项 Node 测试、10 项安装故障测试，共217项**。证据见 [本次源码与软件报告](../audit/v0.2.2/review-dependency-source-verification.json)、[独立代码审阅及可复运行命令](../audit/v0.2.2/review-dependency-independent.json)和[补充证据清单](../audit/v0.2.2/review-dependency-evidence-index.json)。旧冻结报告保留原意，不以作者自检代替非作者验收。

当前仅同步候选源码，稳定版和安装保持不变。旧原生运行时报告仍只证明各自绑定的历史源码；本次变更没有通过可见 DSH 的已部署原生验收，不能把单元测试、合成容量或 GitHub 推送写成运行时通过。完整 A 题、B/C 图文整改和最终发布条件仍须另行完成。
