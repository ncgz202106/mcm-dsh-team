# v0.2.2 候选：共享根激活池的只读容量观测

这是候选源码和操作契约说明。当前稳定安装仍为 v0.2.1，本文不证明候选已加载、当前会话有空余名额或真实原生验收已经完成。不得为验证本文而启动用户禁止的隔离 Host，也不得热替换正在运行的预设。

## 观测范围

已检查的 SDK 0.2.1-rc.2 将 `maxActiveSubagents` 应用于共享根激活池。同一个实际根下面的建模、论文和可选编程主管及其孩子共同占用该池；等待、闲置、closing 中的已驻留孩子也占槽。不同根可以拥有不同池。因此该值不是整个 Desktop 的全局上限，也不是 Team 成员数。

候选 `mcm_root_pool_capture` 使用既有注入服务，只读当前调用 Agent 的实际池：检查实际根、直属所有权链、服务、管理器、预留集合、驻留记录、待发布 materialization 和关闭状态。不会调用 `rootPool()`、`reserve()`、创建／恢复／中断孩子，也不代写项目文件。来源、对象形状或绑定不支持时返回 unknown。

来源检查限定于固定版本、官方导出构造函数身份、执行中类／方法的指纹和磁盘 bundle SHA。包的解析来源必须与实际注入的官方实例相符；仅在磁盘找到一个同版本副本不够。它不认证每个已加载闭包辅助函数，不提供操作系统隔离，也不保证未来 SDK 的内部结构相同。真实安装下的来源解析和原生调用仍须单独验收，离线 mock 不证明这一点。

## 捕获和派发

1. 队长登记任务、版本化输入、独占写入范围和实际角色要求。
2. 实际派发者读回自身身份，并运行 `mcm_root_pool_capture({})`。管理者可以是根队长，也可以是根下面实际驻留的建模、论文或可选编程主管；叶子无派发职责。
3. 管理者若已有任务预分配的独占 `allowed_write_paths`，可将返回的 `snapshot` 原样保存到该目录，例如 `tasks/PAPER-01/runtime-pool.json`，并在预检中显式使用 `snapshot_path`。观测工具本身不代写；实际保存仍须满足文件所有权规则。管理者不得改全局 `config` 或 `.mcm` 登记；它们仍由队长单写。没有授权分区时，才通过父级转交队长保存，不能自行扩大写范围。通知只携带编号、路径、哈希和状态；捕获过期须重新获取，不能为等待转交延长许可。
4. 同一实际调用者在捕获有效期内运行 `mcm_dispatch_preflight`，再使用完全相同参数调用原生 `subagent`。派发前和原生工具体中再次检查任务与捕获。深度 2、保留应急名额、暂停、输入有效性和一次许可仍适用。
5. 原生创建后读回真实孩子角色、父级、深度和目录，由队长绑定实际身份。创建成功不代表成果通过。

快照明确标记 `allocation_scope="root-activation-pool"`，包含调用者和根的标识、进程内容量域、时间、来源、`pool_capacity` 和真实记录。主管的捕获不能换成队长捕获，即使两者属于同一池。重启、同 ID 对象替换、服务／管理器／池替换、来源或限额改变、预留变化和过期都会使旧捕获失效。文件中的布尔值、人工复制的 JSON、旧进程文件及 CLI 输出不能创建进程内捕获记录。

第一次派发前可能还没有池。只有固定源码不变量和实际服务状态共同证明该根没有池、驻留或未完成物化时，才可报告已证明的零预留；不能由“列表为空”猜测为零。第一次创建会形成真实池并使原捕获失效；下一次派发必须重新捕获。逻辑容量域仍属于同一根，不能借池首次创建丢失上一轮派发的记账。

预留已存在但孩子尚未发布时，工具可以读到预留数量，却无法编造孩子 ID。它报告对账缺口并拒绝准入。容量满时保持 queued，只有确认实际释放并重新捕获后继续；不反复 spawn 探测，不把中断或等待当作释放。

## 离线 CLI 的含义

项目的 `mcm.py runtime --snapshot <快照路径>` 是诊断，不是原生授权。对新格式它检查有界结构、身份、local／external 记录、closing 布尔值、重复项、数量对账、限额和时区／新鲜度。`advisory_effective_total`、`advisory_normal_available` 等只依据文件声明做估算；待发布预留、缺口、陈旧和用户暂停均不会建议准入。

即使结构和估算都正常，CLI 也始终返回：

```json
{
  "native_validation_required": true,
  "native_capture_ledger_verified": false,
  "capacity_known": false,
  "admit_one_task": false
}
```

CLI 不持有实际进程的 Agent、池或捕获账本，不能核验它们。`advisory_can_admit=true` 只表示文件声明下存在预算余量；它不能替代 `mcm_dispatch_preflight`。旧 `allocation_scope="host"` 格式继续供历史离线计算兼容，新版原生门禁不据此放行。

项目任务的 `snapshot_path` 指向本项目内文件，不修改队长维护的全局默认 `runtime_snapshot`。每位主管使用自己捕获、自己分区内的文件即可完成预检，避免把60秒证据窗口消耗在不必要的队长代写往返上；同池的不同调用者仍不可互换捕获。

## 验证与限制

离线测试应覆盖多个根、主管与叶子深度、首次池创建、待发布预留、关闭／回收、同 ID 实例替换、来源漂移、伪造 JSON、过期、应急名额和暂停。构建清单应绑定观测源码。它们证明特定源码的离线行为，不能写成当前 Desktop 容量或原生模型调用已通过。

候选正式安装仍须安全空闲点、备份、官方更新和可见新会话中的真实核验。当前科学演练、原暂停项目和 H0／H1／H2／H3 人工关口不因源码维护或同步而改变。

`rehearsal-v2/` 的协议与报告保留为历史冻结夹具，不把其旧Host口径改写为新观测通过。新项目使用当前 `project-template/`；历史夹具、合成单元测试和当前可见DSH的原生验收须分别记录。
