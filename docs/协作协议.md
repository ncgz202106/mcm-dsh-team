# MCM DSH 协作协议 v0.2.0

12类预设按需实例化，专业角色不靠显示名称绑定。根队长是唯一内部调度与登记人，Codex是模型路线、核心结果、论文整合三个检查点的技术总监；共享编号工作包、版本化成果与真实回执，不引入第二套全局任务板。

## 角色树与派发

- 队长→建模负责人→三个专项建模实例，先独立候选后交换比较。
- 队长→两个编程实例，默认核心求解、实验与导出。确有独立任务才增第三实例。
- 编程主管mcm-code-lead默认不启动；启用后只派编程叶子，自己和孩子一起计入授予配额。
- 队长→论文负责人→写作、科研图表、排版。图表任务可拆定量和示意两实例，不再加主管层。
- 证据数据、独立验证、审阅老师直属队长，验证角色不在作者分支下。

最大深度2。原生spawn显式agent_preset、绝对cwd和分区，创建后读回preset/父级/深度/工具。不能把Team成员名当真实预设。叶子不提供本包委派插件，但全局工具可能叠加；行为约束不等于系统隔离。

项目默认预算不证明Host容量。真实Host、项目预算、应急预留共同限制调度；Team8与Host总量分开。等待中的主管仍占位，空闲/中断不等于释放。满额先queued，确认资源回收才派，不盲重试。

## 任务、上下文、交接

任务卡锁定目标、输入及版本、owner_agent_id、可写范围、输出、依赖、验收、技能、时间/配额和升级对象。context pack只携相关记录索引，长历史按需读取。产物交接再读回路径/版本/哈希，作者自报不能代验收。

同级通知经共同父级转发，仅编号、位置、版本、状态、问题和收件角色；技术正文在项目。每份文件一个实际写入者，公共入口/符号/引用库单独指定；论文负责人唯一整合主稿。接管需要明确交接，期限和回收优先于旧grant。

当前依赖闭包内失效成果会阻断，未被引用的历史stale/retracted只提示保留。上游变更使对应结果、图、摘要失效，不手改数字掩盖。

## 科学与论文闭环

1. H0锁题问、数据、规则和交付；同时建立可编译论文骨架及证据图表清单。
2. 三候选盲写，建模负责人统一符号、假设、公式接口与验证方案，提交H1。
3. 两编程实例分区求解；验证手独立重跑，建模团队解释、敏感性及改进，提交同代H2。
4. 论文按用户框架滚动整合，图表消费明确结果版本，摘要最后核数字。
5. 固定版本独立审阅→队长派整改→作者交证据→非作者复验；逐页PDF检查后提交H3。

H2绑模型/结果/同代验证，H3绑确切PDF及消费结果。纯排版变化重查PDF，不自动改变科学批准。真实用户确认是必要条件；技术检查不替人签署。

默认最多三轮集中整改，blocker不能以高分或风险接受放行；仍阻断则回退或缩减主张。内部100分只帮助排序，不预测O奖。

## 图表与专项Skill

图表负责人先规划主张和证据，粗图附一句发现，通过后精修。全篇通常1–2张方法/框架图，数值结果、验证、灵敏性按证据需要。最终12pt、白底、语义配色与线型、统一单位精度、清晰图注；保留PDF/SVG/300dpi PNG和源码。

每个任务一个主Skill，按需辅助。发现、读取、实际执行、产物验收分别留证；缺依赖时不能宣称使用成功。shumo2/shumo-core等全流程入口不自动调用，包括间接引用。专项方法不改用户框架、模型或权限。

编程/验证核数，论文核表达，排版核入稿，独立审阅看全图及最终页。编译、内容完整、视觉分别记录，作者不自签独立验收。数学错误回建模团队，引用精简冗余而保留必要来源。

## 暂停、恢复与故障

用户整体暂停优先于队列、心跳、旧批准和恢复包；预设升级不会恢复旧演练。只在真实用户明确范围内恢复。当前项目、模型、结果、批准记录不因安装新版而迁移或覆盖。

缺Skill/依赖、角色继承错误、输入字节不符、错代验证、PDF裁切等先停受影响链并报队长。安装失败按备份回滚；项目恢复输出独立目录，不覆盖活项目。
