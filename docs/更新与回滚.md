## 更新前与标准路径边界

1. 保留旧版与独立候选，完成测试、图表样例及清单。
2. 只读预检核源、目标、profile和桌面状态；CheckOnly不写插件/profile，但会拒绝已变化、不一致或不安全路径。
3. 保存所有工作并正常退出DSH。官方CLI写profile，不能与活跃Host更新；脚本不强制关进程。备份后、实际切换前会再次确认DSH仍已退出。

```powershell
pwsh -File tools/update-dsh.ps1 -DshCli 'E:\dsh desktop\resources\runtime\cli\bin\dsh.cmd' -CheckOnly
pwsh -File tools/update-dsh.ps1 -DshCli 'E:\dsh desktop\resources\runtime\cli\bin\dsh.cmd'
```

可选-Profile（默认desktop）、-BackupRoot。默认备份写入本工作区work/v020-install-backups的时间目录。更新器先备份插件完整树及相关profile文件，验证路径/存在状态/完整字节哈希，再校验暂存、切换标准目录，并调用官方plugin add --save-exact。除MCM依赖外的包配置、bundle声明、实际依赖解析与运行文件也须保持一致。

## 回滚先预检

使用本次真实备份目录，它须包含installation.json和被哈希绑定的备份文件：

```powershell
pwsh -File tools/restore-dsh.ps1 -BackupDirectory 'C:\实际备份目录' -CheckOnly
```

预检可在桌面开启时运行，返回changed=false及是否需要正常退出。它校验备份完整树、profile前后状态、当前标准目录源码字节、其他插件与依赖实际解析；发现备份被改、安装后配置已变化、锁文件缺失或路径不符就拒绝，不覆盖后来的用户修改。

确认预检通过后，保存工作并正常退出DSH，执行：

```powershell
pwsh -File tools/restore-dsh.ps1 -BackupDirectory 'C:\实际备份目录'
```

DshCli默认从安装收据读取，也可显式传-DshCli。恢复会保留当前版本及profile到本次restore子目录，暂存旧版并核完整哈希，再切回目录及profile，调用官方CLI install --offline --frozen-lockfile恢复依赖解析，随后重新核profile、插件字节及无关插件。最终restored_verified才代表所检查旧状态已恢复；启动后仍应检查版本、角色、原会话和其他插件。

## CLI失败与部分恢复

升级失败不会直接报告恢复成功。更新器尝试恢复旧插件/profile及锁文件依赖，再核字节和实际解析；完整通过记rolled_back_verified。若离线缓存不足、锁文件缺失、CLI恢复失败或核对失败，记rollback_partial及rollback_errors，保留备份和失败现场。

回滚本身失败时，会尝试恢复回滚前的当前版本；成功记restore_failed_current_version_recovered，否则记restore_failed_recovery_partial及recovery_errors。此时先保持DSH关闭，查看installation.json或restore子目录restore.json，按具体缺口处理；不能只因插件目录看似存在就宣称已恢复，也不要删除备份或反复强覆盖。

## 首次安装入口

```powershell
pwsh -File tools/install-dsh.ps1 -DshCli '实际dsh.cmd路径' -CheckOnly
pwsh -File tools/install-dsh.ps1 -DshCli '实际dsh.cmd路径'
```

现有标准安装转入上述备份更新。首次安装使用官方CLI链接本包bundle目录，须保持路径稳定；严格标准目录更新器不负责自动迁移这种链接。若profile已登记MCM但标准目录缺失，入口拒绝直接覆盖，应先核实际布局。首次安装失败不表示已有可回滚备份，须检查实际CLI结果，不误用其他机器或profile的收据。
