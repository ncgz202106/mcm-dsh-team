# 原生派发门禁与真实角色读回

本说明对应 v0.2.2 候选中的 `runtime-guard-core.mjs`、`runtime-guard-plugin.mjs`、`root-pool-observer.mjs` 和原生 `subagent` 接口。当前稳定安装仍为 v0.2.1；候选源码、离线测试或 GitHub 同步不代表已经安装，也不代表已在可见 DSH 中通过原生验收。具体字节与验收范围以相应 `audit/` 报告为准。

门禁服务于 DSH 队长及获配额的建模、论文、可选编程主管。队长仍是全局任务和配置的唯一登记者；主管消费队长已登记的任务，不能自行改写其他分支、人工关口或配额。

## 读回、容量观测与预检工具

| 工具 | 用途 | 不能据此声称什么 |
|---|---|---|
| `mcm_runtime_readback({})` | 读取本会话真实预设、父级、深度、目录与已记录 SDK 工具来源；返回运行时当前配置的每根后代限额（如可读） | 配置上限不等于当前占槽、剩余名额或 Desktop 全局上限；历史 SDK 不等于当前权限枚举 |
| `mcm_runtime_readback({child_session_id: "真实直属孩子ID"})` | 读取本会话的已登记直属孩子，包括已结束孩子的历史 Session 元数据 | 不加载或恢复孩子；不能拿角色名字代替真实 Session ID，也不授权读取别的队伍 |
| `mcm_root_pool_capture({})` | 候选新增：只读实际调用管理者所属的共享根激活池，返回有来源与进程内绑定的容量快照或明确缺口 | 不创建池、预留槽、恢复孩子、代写文件；每根容量不是整个 Desktop 的全局容量，文件中的 `verified=true` 不是原生验证 |
| `mcm_dispatch_preflight({task_id, subagent_arguments, snapshot_path?})` | 核任务、输入版本、角色图、真实深度、绝对目录、写入范围、交接、暂停状态和新鲜容量证据；通过后签发一次性内存许可 | 不创建孩子、不排队执行、不授予任何人工批准，也不提供独立调度平台 |

`mcm_dispatch_preflight` 只向可派发角色提供；叶子角色仅进行职责内工作。论文主管允许派 `mcm-writer`、`mcm-figure`、`mcm-typesetter`；完整角色关系仍以实际工具 schema 为准。

## 派发顺序

1. **读回父级。** 先运行 `mcm_runtime_readback({})`，确认实际预设、初始项目目录和真实深度。最大深度为 2；把论文统筹单独作为根打开时，其孩子实际是 0→1；完整竞赛树通常为队长 0→论文主管 1→图表 2。角色说明中的职位不能代替深度。
2. **登记任务与所有权。** 队长在 `.mcm/tasks.json` 登记具体任务：任务 ID、子角色、输入引用、依赖、独占写路径、验收标准和配额。派发前尚不知道孩子原生 ID 时，可用明确标注的规划标识（例如 `planned:FIG-001`）占位；不能把它写成“已核验的真实 native ID”。把“先报真实身份、待绑定再写入”传入孩子任务。创建后由队长把 `owner_agent_id` 绑定到实际返回的孩子 Session ID，再允许任务写入；成员名称或规划名不构成文件所有权。
3. **观测并绑定容量。** 实际调用管理者运行 `mcm_root_pool_capture({})`，返回的 `snapshot` 由队长按单写入者规则原样保存到项目内文件。`config/runtime.json.runtime_snapshot` 指向该文件，也可向预检传 `snapshot_path`。新快照为 `allocation_scope="root-activation-pool"`，含真实根、调用者、容量域、来源、预留数量和已对账成员。主管必须捕获自己的快照，不能复用队长的捕获。默认新鲜度为 60 秒，且原生预检须在同一进程核验捕获账本和当前实例；重启前文件、自填 `verified=true` 和旧 Host 快照均不授予原生准入。出现待发布预留、陈旧、来源不支持或无法对账时排队，不能臆造 `active=0` 或用 spawn 探测容量。
4. **预检签许可。** 调用 `mcm_dispatch_preflight`，把准备交给原生 `subagent` 的完整参数作为 `subagent_arguments`。只有实际返回 `admitted=true` 才能继续。`cwd` 必须是与本会话初始项目根相同的绝对路径；任务输入的路径、版本、哈希和依赖须一致。未知、过期、暂停、满额、显式 `admit_one_task=false` 或任务不符时，保留待办并报告具体缺口。不能把一次 spawn 当故障探针替代容量核实。
5. **原生创建。** 在许可有效期内，以完全相同参数调用原生 `subagent`，仍须显式传 `agent_preset`。一次许可至多使用一次、最长不超过 60 秒；不得向原生 schema 加入 `permit_id` 等不存在的字段。改提示词、目录、模型选项或任务后须重新预检。派发时会再次检查任务和证据；并发复用、直接跳过预检或陈旧许可会被拒绝。
6. **读回孩子并交接。** 从原生返回值取得真实孩子 ID，再调用 `mcm_runtime_readback({child_session_id: ...})`。核实际角色、父级、深度、目录及工具证据来源，交队长绑定所有权。没有可靠读回时记录 `unknown`，不能仅凭任务卡自证。成果交接另核路径、版本、SHA 和非作者验收，不以许可或创建成功替代质量通过。

当前安装如果没有该候选工具，或实际运行时来源／实例绑定不受支持，配置上限仍可能可读，但真实可用容量保持未知。此时应排队并报告缺口，不能热装源码、启动另一个 Host 或改 `verified=true` 自行放行。更多边界见[根激活池观测说明](v0.2.2根激活池观测.md)。

## 最短参数示例

以下是论文统筹派发一个图表任务的逻辑调用顺序。前提是候选工具已正式安装并经原生核验，队长已经登记 `FIG-001` 并授权图表孩子的独占目录。示例展示工具名和参数；PTC 中的实际调用语法以当前 `run_code` SDK 为准，这些不是 PowerShell 命令。

```javascript
mcm_runtime_readback({});
const capture = mcm_root_pool_capture({});
// 仅在 capacity_known=true 时，将 capture.snapshot 交队长原样保存到项目内文件。
// 此步骤不由观测工具代写；保存后尽快预检，陈旧或实例变化就重新捕获。

const childArgs = {
  description: "FIG-001：结果对照图",
  agent_preset: "mcm-figure",
  cwd: "C:/MCM/practice-01",
  prompt: "只执行已登记的 FIG-001。先读任务 context pack 与 nature-figure，回报真实身份并等待队长绑定，再写授权目录。定量图只消费指定版本结果；交图源、PDF/SVG/PNG、英文图注和SHA，不代签视觉或人工批准。"
};

mcm_dispatch_preflight({
  task_id: "FIG-001",
  subagent_arguments: childArgs
});
// 仅在上一步实际返回 admitted=true 后，立即使用相同参数：
subagent(childArgs);

// 使用原生返回的真实直属孩子 Session ID，不能填写规划名：
mcm_runtime_readback({child_session_id: "<原生返回的真实孩子ID>"});
```

父会话原始项目根必须真实等于示例 `cwd`；使用时替换成自己的绝对项目路径。若显式指定快照，`snapshot_path` 使用项目相对路径，例如 `audit/runtime/paper-lead-pool.json`，不能指向项目外文件。

本地 `mcm.py runtime` 能检查新快照的结构、时间和记录对账，并给出 `advisory_*` 估算；它不持有原生进程的捕获账本，所以始终返回 `native_validation_required=true`、`capacity_known=false` 和 `admit_one_task=false`。不能把 CLI 的空余估算当成一次许可。旧 Host 格式仅保留兼容性的离线计算语义，不能用于新版原生准入。

## 拒绝后的处理与保证边界

- 收到 `MCM_DISPATCH_DENIED` 时按错误处理：补真实容量证据、更新陈旧引用、解决写入冲突或等待释放；不要换 Team 成员、外部 Codex／Claude 子 Agent 或另一根会话继续同一派发。
- 用户暂停保持优先。用户真实恢复后，重新读取状态并预检；旧许可、旧 `grant=true` 和计时结束都不能解除暂停。
- 门禁在正常工具执行管线上检查原生派发，并拒绝 MCM 角色通过全局替代委派入口绕过；SDK 中看得到某个工具名不表示该调用会获准。
- 这是项目和工具流程约束，不是 OS 隔离、任意 shell 命令封禁或对所有外部进程的安全认证。它不改变人工关口，也不代替模型验证、图表视觉验收或正式提交确认。
