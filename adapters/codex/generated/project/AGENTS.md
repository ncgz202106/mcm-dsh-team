# MCM 项目协作约定

本项目用于 MCM A/B/C。内部交流与记录使用中文，正式论文和图注使用英文。质量和可验证性优先；内部评分用于诊断，不代表官方评分或奖项承诺。

## 开始工作前

1. 确认工作目录是实际比赛项目根，存在 `.mcm-project` 或 `.git`。不要在预设安装目录写比赛成果。
2. 读取队长任务卡、`config/contest-mcm-2027.json`、`config/gates.json` 和相关模型/成果版本。
3. 读取本文件、相关protocol和Codex实际工具schema。运行约束由Codex适配层生成；角色配置文件存在不等于已加载。
4. 检查 `.mcm/{tasks,artifacts,issues,decisions}.json` 的相关记录；四个文件统一为 `{"format_version":1,"records":[]}`。资料和 AI 用途登记可另用 `evidence.json`、`ai-usage.json`，不是四个必需登记的替代。

## 必守边界

- 根Codex队长唯一实际派发，按已知会话容量与项目预算排队，保留应急位置；未知容量串行。容量事实、项目配额、角色配置与工具权限分别记录。
- 物理派发深度1。主管拟定任务，根创建所有执行角色；三位建模手初期盲写，programmer默认两个互不覆盖实例，可选code-lead默认关闭。独立verifier不兼任被验成果作者。
- 三位建模手初始独立盲写，收齐后才交换方案。模型、编程、检索的技术联系通过队长转发，不能假装 peer 通信已存在。
- 每文件单一写入负责人。队长独占四个全局登记和 config；子角色写独占任务目录，主管整合。共享读取不等于共享并发写。
- 原始数据一经登记不可覆盖；运行、图表和 PDF 使用独立版本目录。上游变化使下游失效，禁止只改论文数字。
- `approval_state=draft|verified|approved|invalidated` 独立于生命周期 `status`。文件存在、`current`、编译成功或作者自报均不表示批准。
- 不编造来源、数据、运行日志、审阅通过和人工确认；合成演练必须 `synthetic=true` 并与真实成果隔离。

## 人工确认

| 正式 ID | 简称 | 真实用户确认内容 |
|---|---|---|
| `H0_TOPIC` | H0 | 题目选择、规则版本、交付与时间约束 |
| `H1_MODEL` | H1 | 主模型路线、关键假设、重要证据缺口 |
| `H2_RESULTS` | H2 | 关键结果、解释和结论边界 |
| `H3_RELEASE` | H3 | 最终 PDF、技术审查和正式提交清单 |

批准绑定成套 `artifact_id/path/version/sha256`（旧记录可无path，仍须解析登记路径和真实字节）；核心变化使相关关口失效。H2只绑定模型、结果与验证；活动稿/PDF归H3，H3技术验收必须消费仍有效的H2。只有队长整理用户真实回复并写确认记录。等待不等于批准。H3 批准也不自动授权外部上传，提交按用户明确指示执行。

## 交付与审阅

任务、模型、图表、来源、问题和交接使用 `templates/`。所有重要定量主张可追溯到真实来源/假设、模型、配置、结果和论文位置。模型到代码须有公式—函数—输入/输出—验证例契约。

作者先自检，再由非作者复核；独立审阅问题由非作者验证关闭。`blocker` 禁止接受风险放行；三轮集中整改仍阻断时回退或缩减结论。论文从骨架开始滚动写作，定量结果与摘要仅消费批准成果。编译成功之外必须检查 PDF 实际页面。

## v0.2 检查点协作与上下文

v0.2.1增加论证、跨问传递与摘要内容卡，见[论证与页面设计](protocols/07-argument-and-visual-design.md)。填好的卡按既有制品登记并通过任务inputs引用，沿用版本/哈希核验；不新增派发权限或更改人工关口。

Codex根队长负责全部日常调度与全局登记；独立审阅由非作者角色承担。主管只整合授权文件并提出下游任务。不能把检查点意见当作人工批准。

实际用户暂停优先于既有任务、旧grant和自动化心跳。队长记录config/runtime.json的pause_state；暂停期间不派发、不写求解产物、不继续整改。只读检查可在用户授权范围进行；只有真实用户恢复才解除。CLI协作式拒写不等于OS隔离，也不能替代原生会话取消/暂停能力。

派发前运行 `python scripts/mcm.py --root <项目根> context-pack TASK_ID`，只读取该任务输入闭包、相关决定、未关闭问题、独占写范围、技能、验收与暂停状态。过期引用或预算截断时先修任务包，不能搬全部聊天历史充数。技能先读对应SKILL.md，交接记录实际读取与应用；工具/产物必须实际读回路径和SHA后才报交付。新增skills/readback字段对旧任务向后兼容，不把缺字段伪造为已执行。

同路径改写须限时交接：原作者确认、源SHA、接收者、允许路径、grant与到期时间。新的reclaimed_at优先于历史grant=true。同一文件只有一名活跃写入者，主管不因管理整棵子树自动获得所有子文件写权。


## Codex能力与接收入口

# Codex 美赛团队运行层

根 Codex 是唯一实际调度者、全局登记者与交付整合者。12类科学职责保持，所有实际子 Agent 均由根创建，物理深度1；主管提出任务和验收建议，不自行创建后代。身份以真实工具回执为准，任务名称不能证明原生角色已加载。

先读项目AGENTS、相关任务context pack和当前工具schema。继承当前模型和权限；本包不改变provider、访问模式或安全设置。实际工具缺角色选择/身份/拦截观测时报告unknown，strict预检不通过；配置文件存在不构成运行验收。

使用 python scripts/codex_control.py --root <项目根> capabilities 和 preflight；派发前须登记唯一任务、输入引用、写范围和验收，执行claim记录唯一attempt。其余参数以 --help 为准。交付使用deliver，接收使用accept，保护与恢复使用protect/recover。也可经现有mcm.py的codex子命令转发。

子任务仅写各自授权目录，不改全局登记/主稿/其他作者源码。主管提出集成补丁，唯一文件负责人整合。成果必须读回路径、版本、真实哈希和依赖；作者不自签独立通过。非作者报告绑定同一候选，科学/视觉/编译验收分别记录。

容量以当前工具可确认的限制和项目预算为界，不硬编码Host上限；未知容量串行，空闲不等于已释放。根持有实际AgentID和任务对应关系。禁止用新的后台Host、其他模型服务或轮询群聊绕过限制。

只传任务摘要和文件引用，独立建模/审阅请求干净上下文，不继承作者完整草稿历史。暂停时停止新派发、请求已知子任务中断并核状态；后到交付仅待查，不能接收。恢复依据真实用户决定，再核验保护快照、输入、所有权和有效批次。

本包提供协作检查，不能防止同权限任意shell绕过。只有实际工具路径拦截测试通过才登记hook_verified；未覆盖路径、失败或未知均保留。人工H0/H1/H2/H3永不由技术测试、等待、角色自报或synthetic演练生成。
