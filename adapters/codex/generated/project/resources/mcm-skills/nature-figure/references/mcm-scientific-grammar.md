# 科研示意、架构与证据图的视觉语法

从用户提供的11张科研参考图提炼，自编迁移方法。参考图的来源、研究结果与获奖身份未核验；它们不是已验证的美赛答案。7个GIF经文件检查均只有1帧，本轮学习的是静态图。原图只留本机，不随本分支分发。

每个任务只读下表相关1–2项。沿用当前模型、用户论文结构、Python/R后端及项目样式；方法图采用已选单一矢量路线。不得因为参考图好看就引入域泛化、神经网络、强化学习或“安全层”。

美赛全文与结果页面先按[mcm-paper-profiles.md](mcm-paper-profiles.md)选主设计，本表只补局部编码与拓扑。紧凑不能删掉真实题问、分组或领域信息；语义浅底、任务带、数值色阶和必要整页图仍可采用。

## 按读者的问题选语法

| 读者需要理解什么 | 参考编号与可迁移结构 | 适用条件和边界 |
|---|---|---|
| 几种情景有何区别 | 图1：三面板重复元素、共同图例、域/类别/状态正交编码 | 先定义颜色、形状、轮廓各代表什么；概念圆圈不是密度、概率区域或统计置信域 |
| 方法如何分类 | 图2：根—方法族—子方法的层级树，括号或对齐连线 | 树边表示归类，不表示因果；方法可重叠时用带交叉归属的DAG或表格，不假装互斥 |
| 数据如何进入训练、检验及部署 | 图3：来源、划分、更新、模型、独立测试的分阶段结构 | 箭头注明实际传递对象；训练/验证/测试及信息截止真实分离，图上分框不能证明无泄漏 |
| 新方法究竟改了哪一处 | 图4：共享骨干、分支、突出新增接口，旁注解释差异 | 同类节点同尺寸；每种颜色只表达一个机制角色，不把多个新名词堆进同一框架图 |
| 多模型如何汇总 | 图5：共享输入、并行重复组件、清楚的聚合终点 | 注明投票/加权/堆叠等真实汇总方式；少量代表节点说明构件，不绘无意义全连接毛线球 |
| 不同年份/组的证据如何分布 | 图6：规则点矩阵、共同图例、短标签与映射表 | 统计单位、检索范围、去重与分母明确；非负计数通常用顺序色标，零与缺失分开 |
| 两组组成有何变化 | 图7：相同类别保持同色、直接给百分比 | 跨组优先对齐的百分比条或点图；饼图适合少量互斥且穷尽的部分，不用荧光绿、立体厚度或碎片化图例 |
| 决策与环境怎样闭环 | 图8：动作正向、状态与反馈返回，命名独立通道 | 明确每条箭头方向、变量与时刻，实线/虚线区别当前/后续或不同类型，不能一图多义 |
| 约束机制改变了哪里 | 图9：动作通道中的门控模块；反馈通道按真实接口独立返回 | 动作过滤不自动意味着奖励修改；“Safe”字样不能代替可行性、动力学和误差依据 |
| 候选如何变为满足条件的选择 | 图10–11：区域、边界、候选点、修正点及方向 | 先定义可行集/不确定集/距离/更新算子；定义不全只画概念关系，不补造投影或可达性算法 |

## 用视觉通道表达不同含义

图3还提示一个命名陷阱：标为meta-test/query的集合可能参与训练期的元更新，并不因名称含test就构成独立最终检验；核对真实更新路径与信息截止，外层未见域评估另列。这里学习数据角色的区分，不据参考图替实际实验宣告无泄漏。

先写一个简短编码表，再绘图。例如：颜色=来源/机制，形状=类别，填充=已见/未见，线型=当前/下一步。不是每幅图都要用全部通道；相同含义在全部面板保持一致，同一通道不要同时代表两个无关变量。灰度下仍可通过形状、线型与直接标签识别关键对象。

概念示意写明`Schematic`，合成演练写明`Synthetic`；实际计算图则绑定结果版本。概念图中的点数、距离、圆面积、包围关系和箭头长度默认不具有数值含义。若需要面积、距离或概率解释，必须来自真实定义与数据，并补坐标、单位或图注说明。

计数图固定观察窗口与类别全集。没有记录不等于零；缺失不能参加百分比归一化而不说明。只有类别互斥、穷尽且分母已知时才画“组成”；方法可多标签归类时使用各自频次/覆盖率，不把总和强制变成100%。小样本显示计数与分母，而不只给百分数。点面积编码数量时面积与数量成正比，不以半径成正比。

## 框架图与反馈图的可读性

默认从紧凑的论文矢量图开始：无框分类与轻量分组、必要的细线方框、短标签、明确通道。装饰性大圆角卡片、无语义的逐框大面积彩底、粗重轮廓、装饰阴影/发光、无信息渐变、荧光红绿和巨幅图内标题不进入默认示例。图题和较长解释放图注，画布随真实内容安排，不能用大片空白制造“高级感”。这约束本项目科研图，不替换无关UI或品牌设计的风格。

1. **先排节点，再接箭头。** 主数据流通常左到右或上到下；反馈沿外侧独立通道返回。节点、标题、图例与箭头标签都预留空间，转弯不要穿字或贴着边框走。
2. **重复组件要真一致。** 对齐同类节点的边缘、中心、尺寸与端口；相同模型多实例用少量清楚代表项及省略号，不重复画几十条神经连接。
3. **每条重要箭头有语义。** 分别表达数据、参数更新、约束、动作、状态或奖励；归类边不画成因果边，集合边界不画成数据流。箭头注明传递的实际对象，必要时给单位与时刻。
4. **让新增机制最显眼。** 共同骨架用中性灰，新增模块用一个强调色；次级分支低饱和。颜色读取项目配置，用浅色填充和深色边线保持对比，不增加一套近似色号。
5. **字体和线条服务读数。** 英文与数学符号的大小、下标和斜体协调；在最终入稿尺寸检查，不从低分辨率原图复制字体比例。12pt核心标签、清晰线宽、合适箭头头部；拥挤先重排、换行或拆图。
6. **分面用于比较。** 面板相同位置代表相同角色，先画共同结构，再改变需要比较的部分。共用图例放在面板外，避免反复查找；面板编号与正文引用一致。

“高级”来自信息层次、比较效率和结构准确。当前参考主要是二维机制关系；分类树、训练流和反馈通道通常优先二维。保留项目的条件3D偏好：真实空间、两独立连续变量的响应面或三个实际变量的结构适合时评估3D，并配二维读数；不将所有节点画成立体卡片。

## 写入现有图表任务

在现有figure-contract的`figure_type`与`panel_plan`中记录：选择哪种语法、各面板的问题/角色、真实输入字段、主要发现和编码说明。示意图以实际模型接口与公式为依据；图注说明符号、边界和非定量部分。无需另开总控或增加人工关口。

- 情景/集合示意、计数矩阵与组成条形：`scripts/mcm-evidence-panels.py`。
- 分类树、并行集成、反馈通道：`scripts/mcm-schematics.py`；也可通过已装`fireworks-tech-graph`生成任务专属矢量图，实际用了哪种工具就记录哪种。
- 曲线、残差、灵敏性、权衡、空间分面：沿用`mcm-gallery.py`；曲面和空间轨迹沿用`mcm-advanced.py`。

脚本是原创合成配方，不是从原图恢复出的真实算法。只选与任务匹配的例子；真实项目必须重新绑定冻结结果或模型接口，不通过删除Synthetic标签把演练变成实证结论。

## 完成后的检查

核完整图的标签、箭头方向/端口/相交、图例、灰度与面板间对齐；计数和组成再核全部数值、零/缺失、分母与统计范围。字体/几何检测与语义检查分别留证。代码运行成功不证明拓扑准确或审美通过。

最终图插入实际页面后，按`paper.py finish`与现有非作者审阅闭环检查字号、裁切、图注、引用和留白。动作过滤图若没有数学验证，最多解释结构；训练框图若没有划分证据，不得写成无泄漏；可行域图不能靠涂一片绿色就宣称安全。图11的函数与集合定义未知，本轮不重建其算法。
