# O 奖论文固定骨架与案例迁移

## 使用边界

将本文件作为本项目 MCM A/B/C 论文规划、写作、图表和独立审阅的**共享默认骨架**。结构来自公开论文案例，案例表也收录 ICM 范文供方法迁移。比赛要求和评分依据以当年官方材料为准。

- 保留当年题目和官方规则的最高优先级；页数、字号、匿名、引用、AI 报告和提交方式必须另行核验。
- 固定的是论证顺序和证据职责，不是模型名称、图表数量、关键词数量或某篇范文的措辞。
- 题目要求的 memo、letter、flyer、budget 等按题意加入，不因套骨架而遗漏。
- 仅迁移方法；不得复制范文句子、图表、参数、结果或把获奖身份当作正确性证明。

## 一、固定的七部分主框架

除当年官方模板另有明确结构外，默认保持以下功能顺序，不在写作中途随意改成期刊式章节：

### 1. Title / Summary / Keywords

- Summary 位于规定首页，最后撰写并可独立阅读。
- 开头交代决策问题和统一框架；随后按任务写“方法＋量化结果＋意义”。
- 给出至少一项验证或基线证据、最终建议和主要边界；数字带单位、样本/时间和比较口径。
- 不用算法清单替代答案，不在结果未冻结时写死摘要数字。

### 2. Problem Restatement / Analysis / Data

- 把题目转成输入、输出、约束、评价标准和跨问依赖，不长段复制题目。
- 说明数据来源、范围、单位、缺失/异常、预处理和信息截止线；预测任务防止未来泄漏。
- 末尾用一张简洁研究总览或短段落说明“数据→模型→任务→验证→决策”，箭头必须对应真实变量或文件接口。

### 3. Assumptions / Notation

- 每条强假设说明必要性、适用尺度、依据、影响输出、失败后果及对应检验。
- 不用假设消掉题目的核心随机性、约束或行为反应。
- 核心符号统一含义、上下标和单位；公式、代码字段和图表名称一致。

### 4. Model Formulation / Solution / Results / Validation

按子问组织，而非把全文拆成互不连接的算法展示。每个子问默认完成同一微型闭环：

```text
Objective
→ Inherited inputs and units
→ Baseline and its specific gap
→ Assumptions and mechanism
→ Model equations / constraints
→ Parameters and solution procedure
→ Quantified results and figure/table
→ Task-appropriate validation
→ Output passed to the next question
```

- 先解释现实机制，再给公式；公式后解释每一项。
- 写明参数来源、算法设置、随机种子、停止条件和失败处理。
- 每个任务都有结果和验证；敏感性不能替代此处的正确性验证。
- 前问输出必须携带变量、单位、时间窗、点值/分布、不确定性及下游使用条件。

### 5. Sensitivity / Robustness / Error Analysis

- 敏感性回答输入或参数变化如何影响输出；稳健性回答样本、噪声、结构或情景变化下结论是否保持；误差分析回答偏差在哪里及为何产生。
- 扰动范围需有数据、文献或校准依据，不机械使用 ±10%。
- 报告结论、排序、推荐方案或约束是否反转，而非只写“变化小于 X%”。
- 保留不利结果、失效区间和不可定义结果；不得为外观删去反例。

### 6. Evaluation / Conclusion / Recommendations

- 优点只写本文证据支持的优点；缺点写明影响情景、适用边界和补救。
- 结论逐题回答，不引入新数字；建议包含行动对象、优先级、成本/权衡和适用条件。
- 区分模型内模拟、统计关联、样本外预测与因果建议；不拒绝不等于证明，相关不等于因果。

### 7. References → Independent AI Report → Necessary Appendices

- 引用直接支持相应数据、参数、公式或主张；外部图片、地图和图表也须标源。
- AI 使用报告按当年政策独立处理；必要附录只放补充推导、代码或扩展结果。
- 分别核对项目内容预算与官方总页数口径，不以“附录”名义规避页数。

## 二、创新固定为“基线缺口—最小增量—证据链”

每个创新主张填写一张卡：

```text
Baseline gap:
Minimal added mechanism:
Why the problem requires it:
Evidence supporting the mechanism:
Controlled comparison / ablation:
Metric, sample and quantified effect:
Cost and new assumptions:
Failure regime:
Summary / overview / model / result locations:
```

按需使用 B0 朴素基线、B1 标准模型、B2 任务适配和 Ours，不强制每题堆出四层模型。新增模块未改善样本外误差、决策、解释或不确定性时，删除模块或缩小主张，不为“高级”继续加算法。

## 三、图表固定为“论证职责＋真实结果＋最终页面”

- 每个必要结论小节在 `paper/section-visual-map.json` 中绑定主要发现、证据版本和图/表；共享图可服务多节，但各节必须解释对应发现。
- 总览图只解释真实任务接口；结果图给比较和数值；验证图给误差/失败窗口；敏感性图给响应和决策切换；决策页给权衡和行动。
- 先写读者要判断的问题，再从 `nature-figure/references/mcm-visual-recipes.md` 选最相关的 1–2 个配方。高级不等于复杂，禁止无意义 3D、装饰性网络、雷达或 Sankey。
- 图注说明样本、单位、条件、区间方法和来源；正文按“比较与共同条件→关键数字→机制/决策解释→边界”组织。
- 查看完整图和最终 PDF 页面。代码无报错、模板复用或字体碰撞检查均不等于美观、科学和入稿通过。

## 五、共享审阅门禁

独立审阅至少回答：

1. 是否逐题覆盖并维持七部分答案链？
2. 每个子问是否都有目标、基线、模型、求解、量化结果、验证和下问接口？
3. 强假设是否有依据，失败影响是否进入敏感性或边界？
4. 创新是否由同口径对照支持，复杂模块无增益时是否删减？
5. 图表是否支持所在小节结论，单位、样本、区间、尺度和数字是否一致？
6. 摘要、正文、图表、结论和 memo 是否使用同一代结果？
7. 失败情景、弱结论和适用边界是否被隐藏？
8. 当年官方格式、匿名、引用、AI 和提交要求是否单独核验？

发现结构缺口时回到相应责任角色修复，不靠润色、增加颜色或内部评分掩盖。任何内部评分都不是官方分数或获奖概率。
