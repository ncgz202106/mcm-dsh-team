# 03 模型、程序与独立验证

## 三位建模手的两轮机制

首轮收到同一题目、基础数据和公共证据，独立产生完整可求解候选；`blind_phase=true` 时不得读兄弟方案。角色偏重可不同，但每人必须覆盖题意、数学结构、求解接口、证据与验证。待三份盲写交付后，建模负责人发布统一比较包，组织交叉质疑。

选型比较：题意覆盖、假设合理性、数据适配、参数可识别性、可解性、计算代价、解释性及可验证性。先有覆盖全题的可解释基线，再增加能证明收益的复杂机制。不能仅投票，不能为显示复杂度而拼凑模型。模型主路线由建模负责人形成，队长提交 H1_MODEL。

## 从公式到可执行契约

正式实现前填写 `templates/model-contract.json`，至少具备：

1. 每问输入/输出和跨问传递；统一变量、单位、定义域及状态/决策角色。
2. 假设、参数的证据 refs、初始/边界条件、目标函数及约束。
3. 每条公式的稳定 formula_id、表达、适用条件、数值实现函数/模块及输入输出形状。
4. 算法/求解器、容差、收敛或停止标准、不可行/缺失/异常的处理。
5. 结果 schema、单位、精度、随机种子策略、运行配置和预先确定的验证例/标准。

空公式、未定义单位、缺少关键接口或用“某算法”代替实现规格时，契约仍为草稿。编程不能私自补科学定义。模型更改需新版本并通知依赖方；不能为了求解成功偷偷放松约束。

## 求解与实际结果

实现顺序：小规模/可手算例 → 基线 → 核心实验 → 必要的改进与验证。每个运行保存命令、环境、输入哈希、配置、种子、求解状态、日志、原始结果和汇总。异常、不可行、未收敛结果单独标明。统计、优化、机理问题不能只以程序退出成功为验收。

结果从真实文件进入图表和论文，不手抄定量主张。正式运行前可做明确授权的探索试算，但必须标记 exploratory，不得绕过 H1/H2 写成最终结果。

## 按主张选择验证

| 主张 | 优先证据 |
|---|---|
| 预测有效 | 留出/交叉验证、残差、分组误差及无泄漏 |
| 优化有效 | 原约束可行性、共同基线、界或对照算法 |
| 机理合理 | 量纲、极限、量级、结构对照 |
| 数值可信 | 步长/网格/采样收敛、随机重复 |
| 稳健建议 | 参数/情景扰动、不确定性或最坏情形 |
| 参数可解释 | 可辨识性、参数补偿与合理范围 |

灵敏度不等于可辨识性，参数扰动不等于结构敏感性，算法对照不等于科学真实性。只做能改变可信度判断的检验，避免每题堆齐所有方法。

## 三层检查

- 编程自检：实现与运行问题。
- 建模复核：程序是否忠实于模型，结果能否解释。
- 验证复现：非作者依固定输入重跑，并用独立小例、边界或不同实现复核关键数值。

验证报告分别说明运行成功、可重复原结果、足以支持主张三个层次；写明未检查范围和容差。自身修补不能自验关闭。关键验证失败、数据泄漏、约束不可行或数字冲突列 blocker，受影响结果不得进入 H2_RESULTS。

H2 交付包包括批准模型、关键真实结果、验证证据、基线比较、必要敏感性、解释及局限；用户确认其结论范围后才冻结摘要和正式建议。

## 多编程分工与同代验证

默认按solver与pipeline_and_experiments拆两个programmer任务，先给输入输出契约和独占模块范围，维护唯一集成负责人。可选code-lead只在跨模块依赖值得占槽时启动；不用主管也允许队长直接管理编程实例。模型手仍负责数学与敏感性解释，编程不自行改科学定义。验证角色在作者分支外，不能以“不同角色名”替代实际不同实例及独立重跑。

每个候选绑定模型版本、参数、代码内容快照、命令、环境、输入、结果、运行与验证报告。磁盘启动快照不证明Python已加载模块身份；合作式封存不证明OS不可写。结论必须按真实证据范围表述。参数或代码改动后新建运行，不追改旧manifest。验证报告与当前结果SHA成套绑定，新结果登记generation时验证报告同时写result_generation（旧报告的generation字段也可读）；错代或缺代不能用相同数字或相同SHA解释为已复验。旧版未设generation的记录仍可按固定哈希核查。排除随机目录名等字段时要精确列举、说明无科学信息及退役条件，不能泛化忽略所有路径/时间/数字。

H2范围仅模型/结果/验证，最终PDF在H3；活动稿排版改动不应反复作废已批准结果。重大科学变更仍回H1/H2真实用户确认，不因调整范围映射自动扩大批准。
