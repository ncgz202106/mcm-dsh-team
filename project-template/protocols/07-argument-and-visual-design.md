# 论证设计与页面类型

用于已有模型、写作或图表任务，不增加调度层、人工关口或固定图数。遵循用户论文顺序和当年规则，旧合同没有新增内容卡字段时仍按原合同执行。

## 三类内容卡

- `argument-design.json`：把主答案、基线缺口、必要改变、验证、价值、代价与边界串起来。并非强制每题建立四层模型或做同一种检验。
- `question-transfer.json`：除固定制品引用外，说明变量、单位、时间窗、状态/点值/分布/约束、不确定性及下游消费条件。图上有箭头不等于公式中已传递。
- `summary-claims.json`：摘要的主要句绑定实际结果、基准、比较分母、条件、意义与边界；理论题可写条件或界，不凑数字与关键词。

关键假设至少解释适用尺度和依据、影响输出、失败后果及必要检查。只维护与主要结论相关的条目，避免全量重复上下文。

填好的内容卡按既有成果契约登记，派发时作为任务 `inputs` 的固定path/version/sha256引用；沿用context-pack和原生预检已有的依赖核验。不要只在聊天贴一份新卡，或另设未被工具检查的旁路输入。

## 图表证据与样式

每图先确定主要问题，再给每个面板不同的证据职责。例如“实际/预测+残差”“全过程+决策偏差”“机制+受控比较”。共享数据、坐标、单位和情景定义；需要不同尺度时明确标示。不能把多个同义指标拼图当信息增量。

绘图读取项目 `config/figure-style.json`。新项目默认由bundle的单一配置源生成；每个项目可有明确修改，但所有图表实例、图注与排版应消费同一项目配置。不在提示词、脚本或任务卡中各写近似颜色。

最终图内核心文字按项目约束保持12pt；先确定最终物理宽度，再布局。拥挤时精简或拆分，不缩字。位图内部标签不能从正文PDF字体统计中推定为合规。既有figure_check与最终页面人工/AI审阅分开记录。

置信区间、预测区间、参数包络、情景范围与重复运行分布必须按实际定义标注。不要用新计算掩盖模型问题；新估计量、筛选或统计检验转回授权的建模/编程任务。

## 页面类型小样约定

| 页面职责 | 推荐信息组 | 主要检查 |
|---|---|---|
| 模型页 | 目的段、核心定义/公式、变量解释、小算例或示意 | 是否解释选型；公式是否可读；含义是否一致 |
| 结果页 | 问题引导、主要图/表、发现与机制解释、意义 | 是否有比较基准；证据是否真回答题问 |
| 敏感性页 | 扰动理由/范围、响应图、差值或行动切换、边界 | 不只报曲线平稳；参数与结构变化分清 |
| 决策页 | 权衡图或决策表、选择依据、对象/行动/成本/条件 | 技术输出是否成为可执行建议 |

它们是可组合的页面类型，不要求各占整页。图与首次引用尽量同页或相邻页，比较面板尽量同页；适度留白，不用负间距和缩字硬塞。正文与数学字体协调即可，没有唯一“O奖字体”。12TeX pt约等于11.96PDF pt，按真实单位与最终尺寸判断。

## 两遍审阅

1. 叙事压缩阅读：只读摘要、总览、各节首尾、图注和结论，复述同一条答案链；列断点与重复段。
2. 科学和整合阅读：核定义—程序指标—图轴/色标—图注—摘要，检查区间语义、失败情景、重复章节和表格。作者自检不代替非作者验收。

获奖样本只作为设计参照，不构成所有公式、统计或版式正确的证明。不得把私人源材料、个人路径或会话记录写进正式稿和公开参考库。
