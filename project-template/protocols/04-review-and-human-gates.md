# 04 独立审阅、内部评分与人工关口

## 审阅对象与责任

审阅针对固定版本/哈希。作者先自检，另一角色复核接口或内容，审阅老师独立评价整体证据是否支持结论。相同模型的角色分离只是一种过程保障，不能声称完全消除共同偏差。

作者交付后保持 `in_review`，用协议02的显式 `relation:"review"` 依赖把完整输出 refs 和交接文件 SHA 交给 verifier/reviewer。不得为了派发复验把作者任务或草稿预先标 approved，也不得删除执行依赖绕过门禁。报告接受时核真实非作者实例及本次固定输入；pending 计划身份、作者自检、派发准入均不构成独立验收。复验若失败保留失败证据；修改候选后需固定新版本/SHA 并重新交付。

| 对象 | 专业复核 | 独立审阅重点 |
|---|---|---|
| 题意与选型 | 建模负责人、独立候选 | 漏问、误读、主线与不可验证目标 |
| 数学模型 | 其他建模手 | 量纲、假设、边界、接口与替代结构 |
| 来源/参数 | 检索提供、建模采纳 | 原文支持、适用条件与不确定性 |
| 代码/数值 | 编程自检、建模核公式 | 验证角色重跑与关键独立例 |
| 图表 | 编程/验证核数 | 表达误导、可读性与主张匹配 |
| 论文/PDF | 论文整合、排版检查 | 答题、数字、引用、规则及实际页面 |

## 内部诊断量表

以下为团队自拟量表，**不是 COMAP 官方打分公式，也不预测 O 奖**。

| 维度 | 满分 |
|---|---:|
| 题问覆盖与跨问主线 | 15 |
| 模型数学质量与适配性 | 25 |
| 计算、验证与数值可信度 | 20 |
| 结果洞察、敏感性与局限 | 15 |
| 摘要、英文表达与图表 | 15 |
| 证据与复现完整性 | 10 |
| 总计 | 100 |

每项附具体证据、扣分理由和置信度。阶段尚无内容的维度记未评，不随意给零后推算最终分；报告已评可得分与覆盖范围。规则合规、人工批准和 blocker 是独立门禁，不能被高总分抵消。

## 问题闭环

issue 使用 `templates/review-issue.json`，汇入 `.mcm/issues.json`。状态 `open|assigned|fixed_pending_review|closed|accepted_risk`；严重度 `blocker|major|minor`。

每条必须有成果/位置、事实证据、影响、修改建议、责任人和通过条件。作者提交修复与证据后置 fixed_pending_review，原审阅人或队长指定的非作者复核再关闭。作者可提交反证，审阅人应依据证据调整判断。自我关闭或空证据关闭无效。

blocker 不得 accepted_risk；major/minor 的风险接受由队长记录原因、范围和代价，涉及已批准关键结论的则重新确认。每个检查点默认最多三轮集中整改；仍阻断时回退对应上游、缩减主张或向用户决策，不无限追分。

## 四个人工关口

| ID（简称） | 决策包 | 技术前置 |
|---|---|---|
| H0_TOPIC（H0） | 题目、规则、交付、时间与质量目标 | 题目/规则来源版本明确 |
| H1_MODEL（H1） | 主路线、核心假设、保底与证据缺口 | 三份盲写及统一比较，可求解契约 |
| H2_RESULTS（H2） | 关键结果、解释和结论边界 | 真实运行、必要验证、关键 blocker 解决 |
| H3_RELEASE（H3） | 固定 PDF、源码对应及正式提交清单 | 论文审阅、规则、引用/AI 与 PDF 页面检查 |

gate 记录在 `config/gates.json`，结构为 format_version/records，初始全为 pending。只有真实用户明确回复，队长才能实例化 `templates/human-confirmation.json`，写用户依据、时间、scope_refs 和 decision_id。不得预填真人签名、用审阅分数或 CLI 返回替用户批准。

批准只覆盖列出的版本/哈希。核心变化置 invalidated，重新提交相关关口；文字小修是否影响批准由队长按证据判定并记录。CLI 短 alias H0/H1/H2/H3 可映射正式 ID，记录和报告使用正式 ID。H3 不代表无条件授权外部上传。

## 当前范围与暂停优先

H2只批准固定模型、结果及同代验证证据，不绑定持续编辑的paper/PDF。H3技术检查必须先验证当前有效H2，scope直接绑定唯一paper类PDF，并在该PDF登记inputs及完整上游闭包；其中至少有一项result，所消费的结果、模型和验证登记均须在当前H2闭包。仅批准模型、PDF无结果依赖、偷偷替换模型或使用H2外结果均不能通过。H2失效不能以H3高分覆盖。新refs的artifact_id/path/version/SHA必须从同一登记行成套生成，不能用新摘要配旧路径。老refs省path时从登记解析后仍核真实字节。批准语义与字节映射分开记录，修引用不等于Codex或AI重新替用户批准。

实际用户暂停优先于检查点计划及自动化。Codex可以给独立技术意见，DSH队长统一分诊；暂停时不向成员投递新整改、不改稿、不写全局状态。恢复必须来自真实用户，不能把心跳、队列待办、旧批准或旧grant解释为恢复。
